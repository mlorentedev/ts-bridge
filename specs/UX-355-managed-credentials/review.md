- **New gap, same class, one directory state further out — this is finding 1.** The write path validates the *flag inputs* `(f.AuthKey, f.ControlURL)`, but in YAML mode the file set it emits also contains the **preserved** `.env` layer: `buildEnvContent` copies a pre-existing `.env`'s `TS_CONTROL_URL` and `TS_TARGET` verbatim. Runtime precedence is `flags > env > yaml`, so the preserved value is the effective one, and `init` never validates it. A directory that already holds a `.env` therefore still reaches the exact round-7 outcome: `init` prints `Configuration written successfully.` (exit 0) and `connect` rejects the file (exit 1). This is **pre-existing** in mechanism (`buildEnvContent` predates the range) and is **not** a regression introduced by `836fa95` — but it defeats the invariant that commit set out to establish, in the same file, on the same failure mode.
- **Root cause, stated once for both demonstrated instances.** `writeConfig` validates inputs; the emitted artifact is `f.{Target,ControlURL}` **plus** whatever `.env` already held. The validator and the effective config therefore disagree whenever the preserved layer differs from (or is malformed relative to) the flags. Fixing only the control URL leaves the target instance live.

### Verdict

**FAIL** — two **REAL Major** findings, one root cause: `init` validates the flag inputs while the emitted file set also contains the *preserved* `.env` layer, which wins at runtime (`env > yaml`) and is never re-validated. The demonstrated outcome is the exact round-7 failure mode — `Configuration written successfully.` at exit 0, followed by `connect` exit 1 — reproduced with the built binary at `39a97e5` for both the control URL and the target. The round-7 gating item itself (empty-directory `hskey-*` without a control URL) is **closed**, mutation-verified, and its accompanying doc over-claim corrected; no Blocker and no rubric D was found. But the skill's rule is `severity × reality`: a REAL Major gates regardless of authorship, and this one is a demonstrated bug in a file this range rewrote, not a hypothesis.

`dotf spec archive` is **not advisable** in the current state. The gating findings are **outside the contract set** (`proposal.md` / `tasks.md` / `features.json` need no edit, so applying the fix would not stale this review), but the archive refuses without a fresh, passing `review.md`, which this verdict is not.

### Recommended next steps

**The gating item (code + tests; no contract edit required) — findings 1 and 2 are one fix:**
- **`cmd/cli/init.go`:** make the write path validate or overwrite the **effective** layer, not just `f.ControlURL`/`f.Target`. Lowest-friction option: when `--control-url` is given in YAML mode, write `TS_CONTROL_URL` into the preserved `.env` (or drop it) so the value `init` validated is the value `connect` uses; and validate the preserved `TS_TARGET`/`TS_CONTROL_URL` before reporting success, refusing (writing nothing) when the effective pairing is one `config.Merge` would reject. Add a round-trip regression that seeds `t.TempDir()` with a pre-existing `.env` — the assertion the current empty-directory tests cannot make — and re-review.
- **If the human judges "the existing `.env` legitimately outranks `--control-url`" to be the intended contract**, the disposition is a recorded decision: make `init` *warn* that a preserved `.env` layer overrides the flag (still exit 0), or ticket it, and say so in `verification.md`. Surface it — do not let the success message keep implying the flag took effect.

**Outside the contract set (disposition each in `verification.md`; none gate by themselves):**
- **Interactive-wizard Minor:** either add a control-URL prompt or state in the docs that `--control-url` must accompany the wizard for `hskey-*` keys.
- **Carried Minors (`git` trailer, read-time permissions, #391, #399) and the f1-regex durability note:** already dispositioned in earlier rounds or surfaced only. No further action before archive.
- **Docs consistency:** if findings 1–2 are fixed by overwriting the preserved layer, no doc change is needed; if they are dispositioned as intended precedence, `site/src/content/docs/configuration.md` should state that an existing `.env` overrides `init --control-url`.
