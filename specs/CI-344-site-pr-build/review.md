### Verdict

**FAIL** — one REAL Major (the required-check guard does not assert the structure AC1/AC2 and `features.json` claim it does; three mutations of the workflow survive it with exit 0) plus five Minor/Question items, three of which are REAL.

The shipped workflow itself is correct and its live proofs hold up under independent verification; what fails is the **regression contract** that is the only thing enforcing it.

### Recommended next steps

- **Fix the contract guard (tests)** — anchor assertions to structure rather than file text:
  - require the job key itself (`^  site-build:`) and scope the checkout / `npm ci` / `npm run build` assertions to that job's line range, so a rename or a relocation fails the guard;
  - take `run:` values from non-comment lines only (strip comments before matching), so a comment cannot carry the contract;
  - add named regression cases for the three surviving mutants, in the style already used for `PAGES_ACTION_RE` — or, better, a fixture-based suite like `scripts/tests/test-workflow-permissions.sh`, whose "assert on fixtures, not on today's tree" rationale applies verbatim here.
- **No contract-file edit is needed for this fix.** `features.json` f1's behaviour string ("...trigger a pull-request `site-build` job") stays accurate and its `verification` command stays the same file; the fix belongs in `scripts/tests/test-site-pr-workflow.sh` (and dispositions in `verification.md`, which the staleness check excludes). This keeps the next review round cheap: the three contract digests do not move.
- **Record the dispositions** for the Minor/Question rows in `verification.md` — applied, ticketed (e.g. `timeout-minutes`, `--ignore-scripts`, the `pending` features) or declined with a reason. Optionally promote the transferable lesson — *a whole-file text match is not a contract guard; it is a guard against deleting the file* — to the repo's `docs/lessons/` or the vault's pattern catalog, since the sibling `check-workflow-permissions.sh` embodies the opposite (structural, fixture-tested) design.
- **Then re-review, then archive**: `dotf spec review CI-344-site-pr-build` (independence is the point — not the implementer) followed by `dotf spec archive CI-344-site-pr-build`. Archive is **not** advisable now: the verdict is FAIL, and the gate refuses it by design.
