# 2026-07-10

- **A smoke test must never execute the happy path of a long-running, interactive, network-bound or destructive command** — assert flag parsing, validation, error paths and `--help` instead. `connect` blocks until it is signalled, `host setup` mutates the machine and needs admin, and `discover` needs a real tailnet; a smoke case that actually runs any of them does not fail, it *hangs*, and the usual escape hatch is not available — `timeout -sINT` does not stop a Go `.exe` on Windows, so the runner stalls until the job-level timeout kills it with no useful output. The corollary is what makes a destructive command testable at all: `host setup`'s non-admin guard fires **before any side effect**, so the smoke case can assert the guard on an unprivileged CI runner and never reach the mutation, while `host check` is read-only and can simply be run. Rule: before writing a smoke case, ask what the command does when it *succeeds* — if the answer is "keeps running" or "changes the machine", the assertable surface is the refusal, not the success. (`setup()` also clears every `TS_*` var and `cd`s to `$BATS_TEST_TMPDIR`, so a case cannot inherit the developer's environment; `@test` names stay ASCII-only.)

- **A lesson deferred is a lesson lost — three consecutive handoffs recorded this same principle as "not yet written"**: the 07-09, 07-10 and 08-05 session records each carry a line saying the smoke-test principle above still had no entry in this file. The knowledge was not missing, it was never durable: it lived in handoff notes that only the next session reads, and each session re-derived enough of it to keep working and then deferred writing it again. Rule: when a handoff's open-threads list names an unwritten lesson, writing it is the *first* item of the next session, not a nice-to-have behind the next ticket — the cost of writing it is minutes and it was paid three times in re-derivation instead.

- **Never kill a running `go` process on Windows — it corrupts the module cache**: a heavy `go get` (the tailscale v1.80→v1.100 bump) must be run detached and allowed to finish, and two `go` processes must never run concurrently against the same cache. An interrupted download leaves partial entries that later builds fail on in ways that do not point back at the interruption. Rule: treat a module-cache write as non-interruptible; background it rather than running it in a foreground shell you might cancel.

- **A blocked dependency bump is sometimes superseded, not unblocked**: Dependabot #199 (tailscale v1.80→v1.100) sat red on `lint` because of an `SA1019` deprecation in the old discovery client. The resolution was not to fix #199 but to write #252 — migrating `internal/discover` onto the tailscale **v2 client, which is a separate module** (`v2.10.1`, promoted indirect→direct) — and that migration pulled tailscale to v1.100 and, through MVS, cobra to 1.10.2 as well. #199 was closed as superseded rather than merged. Rule: when a bump is blocked by an API deprecation, check whether the migration that removes the deprecation already subsumes the bump; fixing the blocked PR can be strictly more work than replacing it.
