# 2026-09-22

- **A substring test passes on both sides of the bug it was written to catch**: `TestInit_SecurityGuidance` asserted that `init`'s help contains `--auth-key-file`. The help said "consider using `--auth-key-file`" on a command that does not register that flag, so following the advice exits 1 with `unknown flag`, and the test stayed green before and after every rewording, because the defect was in *where* the flag was attributed, not in whether it was mentioned. The SEC-212 re-review found it by running the documented command, which is lesson-030's rule. The fix asserts the shape that matters, `ts-bridge connect --auth-key-file`, and refuses the old wording. Rule: when a test pins guidance text, pin the part that would be wrong if the guidance were wrong. Then remove the string and watch the test fail. A pin that survives its own mutation is decoration.

- **Enumerate the class, not the members you remember**: the process-list warning on `--auth-key` was asserted for `init` only, so `discover`, a third command taking the same inline key, shipped without it and nothing noticed. The replacement test walks `NewRootCmd()` and requires the warning on every command that registers `--auth-key`, with a floor on how many it must find, so an empty walk cannot pass. It went red on `discover` before the one-line fix. Rule: when a property should hold for every X, the test iterates over X from the source of truth (the command tree, the workflow directory, the registry), never over a list typed into the test. A hand-written list is the same blind spot as the code it checks.

- **Contract scope and verification window are different levers, so pick deliberately**: SEC-212 went FAIL → PASS-WITH-GAPS by changing the contract once (AC3 rescoped to what docs can show today, with #306/#307 named as exceptions). The six gaps that followed were dispositioned without touching the contract: F1–F3 fixed in code, F4 ticketed (#348), F5 already owned by #307, F6 declined. All six are recorded in `verification.md`, which the archive gate's staleness check deliberately ignores, as it ignores code. Backfilling `features.json` would have added a fourth contract file and forced a fifth review round for no behaviour change, so it was declined with that reason. Rule: before editing a spec artifact after a review, check whether it is in the contract set. An edit there costs a review round; a disposition outside it does not.
