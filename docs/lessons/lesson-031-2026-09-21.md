# 2026-09-21

- **A hygiene guard that hides its own exemptions is the failure mode it was written to prevent**: `scripts/check-workflow-permissions.sh` allows a checkout to keep its credentials if the `uses:` line names a reason (`# persist-credentials-ok: <why>`). In the first version that disclosure lived inside the failing path — opt-outs were printed only when the run also had findings — so a repository that quietly accumulated exemptions would report **`OK`**. The guard's whole thesis is that a widening must be visible; its own escape hatch was the one thing it concealed, and the clean-run output was the proof nobody looked at. Fix: print opt-outs unconditionally, and pin it with a fixture that asserts both `exit 0` *and* the presence of the word `opt-out` in the passing output. Rule: for any check with an exemption path, write the test that makes the exempt-but-clean case assert the disclosure — "it passed" and "it passed while something was waived" must not print the same thing. Same asymmetry the reviewer registry encodes for `## Review limit reached` (a decline is not a clean review, and silence reads as both).

- **`set -- $var` is not a portable splitter, and a guard that fails differently per shell gets deleted, not fixed**: the same script passed under bash and died under zsh with `cannot parse guard output` — on a *clean* repository, where the correct answer was `OK`. Cause: `set -- $sum` relies on unquoted parameter expansion being word-split, which bash does and zsh deliberately does not, so zsh handed `set` one argument and the seven-field summary arrived as `$1`. The tempting fix was to have CI invoke only bash, which is exactly how "must run under bash and zsh" stops being true in this repo's standards: the portable contract is only real if something runs both. Fixed by splitting with `IFS=' ' read -r a b c … <<EOF` (both shells split on `read`) and validating the summary's shape with a `case` pattern before trusting it. `shellcheck 0.10` cannot lint zsh (`Unknown shell: zsh`), so linting the file is not evidence it works there — the fixture suite runs each case under both interpreters instead. Rule: when a standard says "runs under bash and zsh", the test matrix is what makes it a standard; a claim with no second-shell run behind it is a hope. Related: `check-lessons.sh`'s header already carries the portability notes (BSD `find`, literal token compares) — those exist because each was bought with a breakage.
