# 2026-09-21

- **A hygiene guard that hides its own exemptions is the failure mode it was written to prevent**: `scripts/check-workflow-permissions.sh` allows a checkout to keep its credentials if the `uses:` line names a reason (`# persist-credentials-ok: <why>`). In the first version that disclosure lived inside the failing path — opt-outs were printed only when the run also had findings — so a repository that quietly accumulated exemptions would report **`OK`**. The guard's whole thesis is that a widening must be visible; its own escape hatch was the one thing it concealed, and the clean-run output was the proof nobody looked at. Fix: print opt-outs unconditionally, and pin it with a fixture that asserts both `exit 0` *and* the presence of the word `opt-out` in the passing output. Rule: for any check with an exemption path, write the test that makes the exempt-but-clean case assert the disclosure — "it passed" and "it passed while something was waived" must not print the same thing. Same asymmetry the reviewer registry encodes for `## Review limit reached` (a decline is not a clean review, and silence reads as both).

- **A text-matching guard enforces the spellings it happens to know, so its bypass is a syntax question and every refusal needs its quoted twin**: on the same PR, two different reviewers found two different holes in `check-workflow-permissions.sh`, and they were the same hole. PR-Agent: a commented-out `# - uses: actions/checkout@…` was counted as a real step, so a clean repository went red on line 8. CodeRabbit: `permissions: "write-all"` did not match `:[ \t]*write-all`, and `uses: "actions/checkout@<sha>"` was not merely unenforced — it was invisible, the summary printed `0 checkouts` for a workflow that had one. Both cases passed all eight original fixtures, because every fixture tested a *refusal* and none tested the guard's blindness: a false green is not the failure mode a suite of "does it say no?" assertions can see. Rule: for each rule a matcher enforces, write the case where the violation is present but written differently (quoted, commented, folded, flow-style), and state which of those are knowingly unsupported — `# - {uses: …}` remains a documented limitation here rather than a surprise. Also: count *what you matched*, not just what you rejected; a guard that reports "0 checkouts" about a file containing one is announcing its own blind spot if anyone reads the number.

- **`set -- $var` is not a portable splitter, and a guard that fails differently per shell gets deleted, not fixed**: the same script passed under bash and died under zsh with `cannot parse guard output` — on a *clean* repository, where the correct answer was `OK`. Cause: `set -- $sum` relies on unquoted parameter expansion being word-split, which bash does and zsh deliberately does not, so zsh handed `set` one argument and the seven-field summary arrived as `$1`. The tempting fix was to have CI invoke only bash, which is exactly how "must run under bash and zsh" stops being true in this repo's standards: the portable contract is only real if something runs both. Fixed by splitting with `IFS=' ' read -r a b c … <<EOF` (both shells split on `read`) and validating the summary's shape with a `case` pattern before trusting it. `shellcheck 0.10` cannot lint zsh (`Unknown shell: zsh`), so linting the file is not evidence it works there — the fixture suite runs each case under both interpreters instead. **Correction (2026-09-22):** that last clause was true on a developer machine and false in CI. The GitHub runner has no zsh, and the suite printed `zsh not installed, that shell is UNTESTED` and exited 0, so from #336 until the CI-322 fix every hygiene run certified the two-shell contract with one shell. The suite now fails when a required shell is missing, and the job installs zsh. The rule below held; this lesson's own evidence for it did not. Rule: when a standard says "runs under bash and zsh", the test matrix is what makes it a standard; a claim with no second-shell run behind it is a hope. Related: `check-lessons.sh`'s header already carries the portability notes (BSD `find`, literal token compares) — those exist because each was bought with a breakage.
