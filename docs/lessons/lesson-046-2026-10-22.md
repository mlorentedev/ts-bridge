# 2026-10-22

**An exclusion written for one rule shape catches every rule with that shape.**
BUG-035 dropped every iptables ACCEPT without a destination port, so that
`-m conntrack --ctstate RELATED,ESTABLISHED -j ACCEPT` would not count as an
allow. The same test also dropped `-i tailscale0 -j ACCEPT` and
`-s 100.64.0.0/10 -j ACCEPT`, the rules operators write to trust the tailnet,
so `host setup` still widened RDP on exactly the hosts #479 was about (#483).
Name what disqualifies the rule (a match the parser does not model, a non-TCP
protocol), not a feature that both the bad and the good rule lack.

**Widening a "covers" test needs a guard in the direction it widens.** Counting
port-less ACCEPTs makes `-A INPUT -i lo -j ACCEPT` an allow, and that rule is in
practically every hand-written ruleset. On a `-P INPUT DROP` host, setup would
report `ok` and leave RDP closed. That failure is silent, so it is worse than the
widening it replaces. Exclude loopback explicitly (`-i lo`, a loopback `-s`/`-d`
prefix), and make every unmodeled case fall back to "absent", the
failure that is visible.

**Read the dependency's source before scoping a firewall fix.**
`tailscale.com/util/linuxfw` appends `-A ts-input -i tailscale0 -j ACCEPT` on
every host where tailscaled manages netfilter. The tailnet already reaches the
port there, and `-S INPUT` cannot see it. That is a larger finding than the
ticket in hand, so it is filed as #492 rather than folded in.
