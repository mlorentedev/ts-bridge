# 2026-11-12

**Ownership does not travel with the code that claims it.** The Linux firewall step deletes the
unscoped allow for its port, because earlier releases wrote exactly that rule and `setup` replaces
it with a `tailscale0`-scoped one (#631). Pointing the same step at the ssh port (#521) would have
deleted `ufw allow 22/tcp` and the matching `iptables` copies: byte for byte the rule setup used to
write for RDP, but on port 22 it is the operator's, and removing it can close SSH from every
network. The step was correct for the one port it was written for and silently wrong for a second.
The unit test that pins it was written before the fix and went red with `ufw delete allow 22/tcp`
in the recorded commands. When a "replace what we wrote" step gains a second target, ask whose rule
the match is for each target, not whether the match works. Here the ssh read reclassifies those
rules as foreign (`sshFirewallRead`), so setup reports them `manual` and never deletes them.
