# 2026-10-22

**Read the firewall from its configuration, not from its live view, and only
as root.** On Ubuntu 24.04 (ufw 0.36.2, iptables 1.8.10 nf_tables):

- `ufw status` prints only `Status: inactive` while ufw is off, so a check built
  on it re-adds the rule on every run. `ufw show added` lists the configured
  rules whether ufw is active or not, as `ufw allow 3389/tcp`, and routed rules
  as `ufw route ...`.
- `iptables -C` exits 0 for a present rule and 1 for an absent one. Without root
  it exits 4 on nf_tables, but `iptables(8)` documents only 1 and 2, and legacy
  backends can answer 1, which reads as "absent". So check for root before
  `-C`, and never read a non-root exit status as an answer.
- `systemctl is-enabled` / `is-active` exit non-zero for "disabled" or
  "inactive" and still print the word, so decide on the printed word, not on
  the exit status.

Measure these in a throwaway container (`docker run ubuntu:24.04`, as root and as
a plain user) before encoding them in golden tests (#454).
