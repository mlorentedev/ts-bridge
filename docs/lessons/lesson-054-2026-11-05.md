# 2026-11-05

**A faked runner proves the argv we chose, not that the tool accepts it.** The Windows
power step ran `powercfg /change standby-timeout-ac 0 /change hibernate-timeout-ac 0
/change monitor-timeout-ac 0` in one call. powercfg takes one `/change` per call and
answered `Invalid Parameters`, so the step had failed on every Windows host since it
was written (#603). The unit test pinned that exact argv as the expected call, so the
test asserted the bug. One run on a Windows 11 VM (`dotf vm windows`) found it in
minutes. A step that shells out to an OS tool needs one run against the real tool
before it ships. For this repo that is the local e2e harness (#606).

**A step that writes without reading reports `changed` forever.** The SSDP, UPnP and
network profile steps acted on every run, so a second `host setup` on a converged host
still showed three `changed`. That broke ADR-017's "a second run changes nothing", and
no test noticed, because each test runs a single pass. The harness now runs setup
twice and asserts on the second run. Whatever reads a step's state must also cover the
case where there is nothing to act on: with no Tailscale adapter, the profile step is
`manual`, not `changed` for an empty pipeline.

**Read localized tool output by position, not by label.** `powercfg /query` localizes
"Current AC Power Setting Index". The order of its hex values does not change: the AC
index is the second-to-last value and the DC index the last. When the parse fails, the
step writes the value (fail open toward the action, lesson 053).
