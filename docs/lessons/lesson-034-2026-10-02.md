# 2026-10-02

- **A writer must not accept what its own reader rejects, and two copies of a rule is one bug waiting for a review round**: `ts-bridge init` wrote a configuration that `ts-bridge connect` then refused. Round 6 gated the *format* half (init validated keys with the pre-#398 prefix check while `config`/`credential` had moved to structural validation) and fixed it by delegating to `credential.ValidateKey`. Round 7 found the sibling rule in the same file: init accepted an `hskey-*` key with no control URL and reported success, while `config.Merge` refuses that pairing. The round-6 fix removed one duplicate validator; the duplicate lived in two places. The fix exports `config.ValidateControlPlane` and calls it from the single write path, so one function decides both write and read. Rule: when a file has a producer and a consumer, they share one validator — and when you fix a duplicated rule, search for the other copies of it in the same file before declaring the class closed.

- **The differential round-trip is the test that catches divergence, and it is a property over a grid, not a list of remembered cases**: both halves were invisible to name-scoped tests (`TestInitAuthKeyFile`, `TestInitAuthKeyValidationMatchesConfigMerge`) because each asserted one side in isolation. What catches them is `write → load the way the consumer loads → validate`: for every `(key, control URL, format)` combination, *init accepts if and only if connect accepts*. The grid failed on 8 of 32 combinations before the fix, including cases nobody wrote a test for (`headscale.example.com` with no scheme, an `hskey-*` key with a valid URL). Rule: express the invariant as equality between the two sides and iterate a small grid of inputs; a test that asserts one side's outcome only pins the behavior you already had.

- **"Refuses" is only true if it also writes nothing**: `init` failing with a non-zero exit while leaving a half-written `.env` behind is still a broken onboarding. The test asserts the error carries the actionable flag (`--control-url`) *and* that the config path does not exist afterwards, which is what makes the refusal a guarantee rather than a return value. The same review found the site claiming the wizard "detects the key prefix and configures accordingly" — true of the intent, false of the behaviour — so the claim was rewritten and pinned in the documentation guard that already walks these files. Rule: pair a refusal assertion with the filesystem state, and pin doc claims about behaviour in the same guard as the behaviour.
