# 2026-10-03

Crystallized from the bug fixes merged between 2026-09-28 and 2026-10-01 (#359, #361, #377, #379, #386, #392, #398), which shipped without a lesson at the time.

- **A prefix is a namespace, not a type** (#397 → #398): the managed credential store accepted anything starting with `tskey-`, so an API access token, an OAuth client secret or two machine keys pasted back to back all passed, and tsnet rejected the value later with `invalid key: unable to validate API key`. The live #183 run stored exactly that: a machine-auth value of 120 characters and seven hyphen-separated segments. The fix validates the whole grammar of a node key (machine-auth class, exactly the id and secret segments, no whitespace or line breaks) and shares that one validator between the credential store and config loading. The diagnosis itself never printed the secret: it was classified by prefix class, length and segment count. Rule: validate the full grammar of a credential, not its leading characters, and describe a rejected secret by its shape, never by its value.

- **Validate the resolved configuration, not the first layer that has been merged** (#370 → #379): `connect --profile <name>` ran `config.Merge` (which requires a target, and a control URL for Headscale keys) before `applyProfile`, so a profile-only invocation failed validation for fields the profile was about to supply. Unit tests exercised `applyProfile` in isolation and therefore could not see the ordering. Rule: required-field and cross-field validation runs once, after every layer (flags, env, YAML, profile, defaults) has been applied, and the regression test drives the production Cobra command path, because the bug lives in the sequence, not in either function.

- **A listener collision check compares resolved endpoints, and every new listener joins the whole set** (#377): the SSH bootstrap SOCKS listener was checked against the bridge listener but not against the health listener, and a string comparison would miss equivalent IPv6 spellings and addresses derived automatically. The fix resolves both sides before comparing and covers exact, equivalent and derived addresses. Rule: when a feature adds a listener, enumerate every listener the process already opens and compare normalized endpoints; fixing the one collision a reviewer named is the sibling trap of lesson-033.

- **A test owns every goroutine it started, and the race report names the wrong test** (#385 → #386): `TestAcceptLoopWithDialer` waited for the accept loop to return but not for its per-connection handlers, so a handler's deferred `AddActiveConnection(-1)` was still running when the next test called `telemetry.ResetMetrics`. The `-race` failure surfaced intermittently under the SOCKS5 test name on unrelated PRs. Rule: before a test returns, wait on the handlers' `WaitGroup`, not only on the loop that spawned them; when a race involves global state, read the previous test in the package first.

- **Never assert on an OS port range being bindable** (#387 → #392): a precedence test hardcoded high port ranges that Windows reserves on some machines (`netsh int ipv4 show excludedportrange protocol=tcp` reported the overlapping range), so every bind failed with WSAEACCES and the test failed consistently on one workstation only. The fix injects the free-port selector into the precedence tests and covers the real probe separately against an occupied port. Rule: separate "which port does the logic choose" (inject the selector) from "does the probe work" (one test against a port the test itself occupies).

- **A guard that judges a pull request must not run code that pull request can edit** (#359 → #361): extracting the review-published check into `scripts/check-review-published.sh` added a checkout without a `ref:` to a job holding `pull-requests: write`, so a same-repository PR could edit the script and make the guard report a review that never happened. The checkout is now pinned to the default branch. The same PR fixed a `jq` crash on a comment whose `body` is `null` (`(.body // "")`), a real API shape. The pin landed as a separate PR because #359 was merged manually at its previous commit while the fix was still unpushed. Rule: trusted gate logic comes from the base branch, and a PR is merged at the commit that was reviewed, never while a known fix is still in flight.
