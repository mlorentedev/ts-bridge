# 2026-10-06

Two independent adversarial reviews, run back to back on the two documentation/CI guards still open before a workstation migration (CI-344, CI-348), failed for the same reason. Both guards were written and green; both passed contract-breaking input.

- **A guard over a text format must parse the unit it protects, not grep the file** (CI-344, #344): `test-site-pr-workflow.sh` asserted that `site-pr.yml` *contained* `run: npm ci`, a checkout and the `site-build` job name. Renaming the job, moving the checkout into another job, or replacing `npm ci` while a comment still said `# run: npm ci` all passed; a comment naming `pages: write` and an unquoted `node-version: 22` failed for no reason. Cutting out the job and asserting per step was not enough either: three more rounds found `run: npm ci` parked under a step's `env:`, an `if: false`, a `!site/**` path filter and extra permissions beside `contents: read`, all passing. What held was position, not text: each line keyed by its parent (`with.persist-credentials`, `env.run`), and every block the contract owns compared as an allow-list (exactly these permissions, exactly these filters, no `if:`). Each mutant is a fixture that must fail, next to spellings that must pass.

- **Enumerating the shapes of a forbidden command loses; classifying by region wins** (CI-348, #348): `check-doc-authkey.sh` recognised `ts-bridge …` and `./ts-bridge …`, and each review round found another wrapper that carried an inline `--auth-key` past it: `sudo`, `VAR=1`, `/usr/local/bin/`, `& C:\tools\ts-bridge.exe`, `yes |`, `go run`, quoted paths, a line split after the binary. Four rounds of adding wrappers never converged, because the set of ways to invoke a binary is open. The redesign inverted the question: an inline `--auth-key <value>` inside any code region (fence, indented block, inline span naming `ts-bridge`) is a finding unless it is the one documented `init` exception with its process-table warning nearby. The regions are a closed set the Markdown grammar defines; the invocations are not. Lesson 032's "enumerate the class" still applies, but the class must be the closed one.

- **How to tell before the reviewer does**: mutate the protected file in each way the contract forbids and run the guard. If any mutant exits 0, the guard checks spelling, not contract. Six mutants of `site-pr.yml` took a minute and now all fail.
