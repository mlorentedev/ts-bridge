# 2026-10-06

Two independent adversarial reviews, run back to back on the two documentation/CI guards still open before a workstation migration (CI-344, CI-348), failed for the same reason. Both guards were written and green; both passed contract-breaking input.

- **A guard over a text format must parse the unit it protects, not grep the file** (CI-344, #344): `test-site-pr-workflow.sh` asserted that `site-pr.yml` *contained* `run: npm ci`, a checkout and the `site-build` job name. Renaming the job, moving the checkout into another job, or replacing `npm ci` while a comment still said `# run: npm ci` all passed; a comment naming `pages: write` and an unquoted `node-version: 22` failed for no reason. The fix strips comments, cuts out the `site-build` job, and asserts per step (`run: npm ci` and `working-directory: site` in the *same* step). Each mutant is now a fixture that must fail, next to spellings that must pass — the same fixtures-not-today's-tree rule `test-workflow-permissions.sh` already followed.

- **A command matcher enumerates the ways a command is invoked, not the way the docs happen to write it** (CI-348, #348): `check-doc-authkey.sh` recognised `ts-bridge …` and `./ts-bridge …` only, so `sudo ts-bridge`, `VAR=1 ts-bridge`, `/usr/local/bin/ts-bridge`, `& C:\tools\ts-bridge.exe` and `yes | ts-bridge` all carried an inline `--auth-key` past it. A whole-line inline code span was also read as a PowerShell continuation because both end in a backtick; PowerShell's own rule (the continuation backtick follows whitespace) separates them. Same shape as lesson 032's "enumerate the class": the class here is *invocations*, and a fixture per wrapper is the enumeration.

- **How to tell before the reviewer does**: mutate the protected file in each way the contract forbids and run the guard. If any mutant exits 0, the guard checks spelling, not contract. Six mutants of `site-pr.yml` took a minute and now all fail.
