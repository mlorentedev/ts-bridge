# 2026-08-05

- **A merged PR is not evidence that your commit reached the branch — verify content, not PR state**: PR #267 (route host logs to stderr) merged green, but a follow-up commit that hardened the regression guard never made it. The sequence: a review comment arrived, the fix was committed locally, `master` was merged into the branch remotely by someone else, the local commit was rebased onto that — and the `git push` after the rebase never ran. `gh pr list` then reported `MERGED` for #267, which is true and says nothing about the rebased commit, because a squash merge takes whatever the remote branch held at merge time. The tell that something is off is cheap to check and easy to skip: `git log` showed a local commit whose branch had `[origin/...: gone]`. Rule: after any rebase-then-push sequence, and before writing a handoff that calls the work done, diff the tree — `git diff origin/master HEAD -- <paths>` — rather than reading PR status. Use the **two-dot** form: `git diff A...B` diffs from the merge-base, so on a branch whose content was already squash-merged it still reports every change as new and hides the answer to the question you are actually asking.
- **An assertion that *parses* is not an assertion that *constrains* — pin the cardinality, not just the syntax**: the smoke guard for the `--json` stdout contract validated with `jq -e .`. jq accepts a *stream* of concatenated values, so `printf '{"a":1}{"b":2}' | jq -e .` exits 0. Two adjacent objects on stdout is precisely the shape the bug produced under `--log-format json` — a JSON-formatted log line followed by the JSON payload — so the guard would have passed on the exact defect it was written to catch, and the text-format variant was only caught incidentally, by a first-char/last-char structural check. Fix: `jq -se 'length == 1 and (.[0] | type == "object")'` slurps the stream into an array and asserts it holds one element. Rule: when a contract says "exactly one X", the assertion must say `length == 1`. "It parsed" is a much weaker claim than most guards intend, and the gap only shows up on the failure mode the guard exists for — verify a new guard by running it against a binary built from the pre-fix tree, not by watching it pass on the fixed one.
- **A test file that no CI job executes is documentation, not a test**: `scripts/tests/smoke.ps1` carried a case named "version -v (deprecated flag)" asserting that `-v` prints a version. `-v` is the shorthand for the global `--verbose` flag (`cmd/cli/root.go`) and has never been a version alias, so the case documented a flag that does not exist — and `--version` itself had no coverage at all. Neither fact was noticed because no workflow ever runs the file: the `smoke` job runs the BATS suite on Linux, and `test-windows` runs `go test`, not the PowerShell smoke script (filed as #271). Rule: when a test asserts something false and nobody noticed, check whether it runs at all before assuming the assertion drifted — an unexecuted test rots silently and its rot is invisible in a green pipeline.
