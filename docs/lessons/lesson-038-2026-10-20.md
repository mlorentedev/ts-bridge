# 2026-10-20

**One SDK proxy hook can feed consumers with different protocol assumptions.**
The bootstrap hook returned a `socks5h://` URL for the control hostname. The
control HTTP client understood it, but the pinned DERP client treats every
non-`https` proxy URL as a plain TCP endpoint and writes an HTTP `CONNECT` into
it, so a SOCKS server answered with `incompatible SOCKS version`. Assertions on
the URL's shape passed on both sides of the bug. Prove protocol compatibility
by driving the real SDK consumers (control client and DERP client) against a
synthetic server, and repair the boundary with an adapter in application code
rather than by editing the dependency cache.

**Do not assert a wall-clock duration is strictly positive.** On Windows the
clock resolution can make `time.Since` read `0s` around a blocking call. Assert
the property that discriminates (the dial's own deadline is the configured
timeout, not an ancestor's) and keep the elapsed time only as an upper bound.

**A proxy adapter should not invent its own timeouts.** Reusing a readiness
constant as a CONNECT dial ceiling made failover slower than the direct path.
Inherit the caller's context so the SDK keeps ownership of its deadlines.
