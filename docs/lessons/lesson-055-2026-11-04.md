# 2026-11-04

**Read the tailscale source before trusting the issue's picture of a mode.** #526 expected
tailscaled's nftables mode to keep its rules in their own `ts-filter` tables. In
tailscale.com v1.104.4 that is false: `AddChains` (`util/linuxfw/nftables_runner.go`)
puts `ts-input` in the conventional `ip filter` table that iptables-nft and ufw share,
and only v1.48.0 briefly used `ts-filter`/`ts-nat`. So `nft list tables` cannot tell
tailscaled's mode apart from iptables-nft; the probe that can is
`nft list chain ip filter ts-input`.

**Where the read cannot see the rules, return unknown, never absent.** An absent read
makes setup append `-A INPUT -p tcp --dport N -j ACCEPT`, which opens every interface.
`--netfilter-mode=nodivert` (`AddHooks` skipped) and nftables mode both leave
`iptables -S INPUT` without a jump to `ts-input`, so the reader now looks for the chain
by name before it calls the port unprotected. The extra reads run only when INPUT has
decided nothing.

**Still unproven.** The fixtures come from the source, not from a host running tailscaled
in each mode, and the nft rendering is what `nft` is expected to print. A host without
the `nft` binary and with tailscaled forced into nftables mode stays invisible. IPv6
(`ip6tables`) is not read.

**Correction (2026-11-10, #526): nftables mode is visible to iptables-nft.** A capture
on a real host (Ubuntu 24.04, tailscaled 1.104.4, `iptables v1.8.10 (nf_tables)`,
`scripts/e2e/capture-tsfw.sh`) shows that in nftables mode `iptables -S INPUT` still
prints `-A INPUT -j ts-input` and `iptables -S ts-input` prints the chain. iptables-nft
reads the same `ip filter` table that `AddChains` writes, so the reader sees the
tailnet ACCEPT and calls the port present. That still holds with the `nft` binary
removed. The claim above holds only for nodivert (captured: `unverified`, as designed)
and for nftables mode on a host whose `iptables` is the legacy backend, which this
capture did not cover. The fixtures are now verbatim from the capture, not from the
source. `ip6tables` mirrors the IPv4 chain (`-i tailscale0 -j ACCEPT`) and is still not
read.
