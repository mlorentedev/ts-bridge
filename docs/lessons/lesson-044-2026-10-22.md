# 2026-10-22

**Ask the service manager whether a service exists, not PATH.** xrdp installs
to `/usr/sbin`, which a non-root `PATH` often lacks, so `LookPath("xrdp")`
reported an installed and running service as missing (#478). systemd knows the
unit whatever the caller's `PATH`; `PATH` is the fallback only where systemctl
itself is absent.

`systemctl is-enabled` answers with more words than `enabled` and `disabled`
(Ubuntu 24.04, systemd 255):

- `not-found` (exit 4): no unit, so the service is not installed.
- `static` and `indirect` (exit 0): the unit has no `[Install]` section of its
  own, so `enable` cannot change it. Treating these as "not enabled" makes setup
  run `enable` on every pass and never converge.
- `masked` (exit 1): `enable` fails until `unmask`, so setup reports `failed`
  with the unmask command instead of running `enable` and printing its error.
- `enabled-runtime`: enabled until the next boot only, so not enabled.

Decide on the printed word, never on the exit status (lesson 042).
