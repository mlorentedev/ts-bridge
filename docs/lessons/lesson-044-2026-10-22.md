# 2026-10-22

**Ask the service manager whether a service exists, not PATH.** xrdp installs
to `/usr/sbin`, which a non-root `PATH` often lacks, so `LookPath("xrdp")`
reported an installed and running service as missing (#478). systemd knows the
unit whatever the caller's `PATH`; `PATH` is the fallback only where systemctl
itself is absent.

`systemctl is-enabled` answers with more words than `enabled` and `disabled`.
Measured on Ubuntu 24.04 (systemd 255):

- `not-found` (exit 4): no unit, so the service is not installed.
- `static` (exit 0): the unit has no `[Install]` section, so `enable` cannot
  change it. Treating it as "not enabled" makes setup run `enable` on every pass
  and never converge.
- `masked` (exit 1): `enable` fails until `unmask`. Setup reports `failed`
  with the unmask command instead of running `enable`, and check reports
  `manual`, because setup never unmasks a unit.

Every other answer (`indirect`, `generated`, `alias`, `transient`, `linked`)
means that whether the unit starts at boot depends on another unit. These were
not measured, so ts-bridge does not guess: setup reports `failed` (it cannot
converge) and check `unverified`, both pointing to `systemctl status xrdp`. `enabled-runtime` lasts
only until the next boot, so it does not count as enabled.

Decide on the printed word, never on the exit status (lesson 042).
