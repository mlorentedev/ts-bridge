# 2026-11-14

**A read that guards exposure must fail closed, and canned output cannot prove that it does.** The
first `OpenSSH-Server-In-TCP` read in #781 ran with `-ErrorAction SilentlyContinue`. A provider or
filter error therefore printed `total=0 exposed=0`, and the step reported `ok` for a rule that might
allow every address. The same read compared `LocalPort` with `-contains`, so a `20-30` range was never
matched. In a Go test both reads look correct, because the fake runner returns whatever line the test
supplies. The fix lets only `ObjectNotFound` stand for "absent" and turns every other error into a
non-zero exit, which the step reports as `unverified`. Then the new script ran on the Windows guest
against real rules (absent, a range, scoped, any address). Any PowerShell read whose zero means
"safe" should be exercised on a guest with each of those shapes before it ships. The `make e2e-windows`
pass alone did not exercise it: its ssh case only checks.

**A fixture can encode the bug it should catch.** The MSI test fixture had `BINARY_PATH_NAME: "...sshd.exe" -f x`
and expected `ok`. `serviceBinary` dropped the `-f` argument, and the probe read the default
configuration instead of the service's. A reviewer saw this from the parser, not from the test. When a
parser discards part of its input, give the dropped part a case of its own with a stated outcome
instead of passing it through as decoration.
