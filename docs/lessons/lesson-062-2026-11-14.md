# 2026-11-14

**"Reuse" in a design is a claim about code, and it is the claim a reviewer should check first.**
The first version of ADR-018 said the agent "adds a mode and replaces nothing", because each session would
run the existing `connect --profile`. Two independent reviewers, deepseek and gemini, read the code
behind that sentence and found it false in five places:

- `connect` reads no stdin, so an EOF lifeline would change its contract.
- Go's `ExtraFiles` does not exist on Windows.
- The auto hostname embeds the pid, so every restart registers a new machine.
- The state directory follows `$XDG_STATE_HOME` and falls back to `$TMPDIR`, so a tray and a login
  supervisor can hold two different locks.
- Every process that exits gzips and removes the daily log the others still write (#788).

None of these appeared in the options table, which compared toolkits and ownership models. The
revision declares the child invocation as a contract (`--lifeline`), with its stdin, environment,
ABI and log ownership written down. When an ADR leans on existing code, list the paths it depends on
and read each one for the assumption the new caller changes: stdin, environment, process identity,
and shared files.

**A headless reviewer run hangs silently unless its stdin is closed.** `pi -p` started in the background
with stdin open waited for input for almost four hours and wrote nothing, so it looked like a slow
review rather than a stuck one. With `< /dev/null` the same prompt answered at once. `agy -p` takes the
next argument as its prompt, so `agy -p --mode plan "<prompt>"` sent "--mode" as the prompt and failed
with exit 2. The working form is `-p="<prompt>"`. Run headless reviewers with stdin closed, a watchdog,
and an output-size check, and treat an empty output after minutes as a failure, not as progress.
