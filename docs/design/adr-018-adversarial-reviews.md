# ADR-018: adversarial reviews and their disposition

Two independent reviewers outside Anthropic reviewed ADR-018 at `5d16213` on 2026-11-14. Each got the same red-team prompt and read-only tools:

- `nan/deepseek-v4-flash`, run through `pi`. Verdict: **PASS-WITH-GAPS**.
- `agy/gemini-3.8-flash-high`, run through `agy` in plan mode. Verdict: **FAIL**.

The two verdicts rest on the same blockers: Windows pipe squatting, an environment-derived lock base, the lifeline as an undeclared contract change, and two supervisors. Neither review rejects option B. The operator kept Wails (option F), subject to the Linux tray spike (#789).

The implementer checked each code claim against the tree before applying it. Confirmed: `FileRotator.Close` removes the shared daily log, the auto hostname embeds the pid, `stateDirFor` falls back to `$TMPDIR`, `connect` reads no stdin and hands stdin to the SSH bootstrap, and Go's `ExtraFiles` is unsupported on Windows while `SysProcAttr.AdditionalInheritedHandles` exists in Go 1.27.

## Disposition

The § numbers refer to the revised ADR-018.

| Finding | Disposition |
| --- | --- |
| A1 / F-01 / F-06: pipe squatting, no server authentication | Applied in §2: `FILE_FLAG_FIRST_PIPE_INSTANCE` and `PIPE_REJECT_REMOTE_CLIENTS`. The client opens with SQOS identification and checks the server SID; on Unix it checks the server's peer credentials and the directory mode. No credential goes to an unverified endpoint. |
| A2 / F-02 / F-14: macOS socket path, `sun_path` limit, no `$XDG_RUNTIME_DIR` | Applied in §2: `~/Library/Application Support/ts-bridge/run/` on macOS. On Linux, `/tmp/ts-bridge-<uid>/` with ownership, mode and symlink checks. A path over the limit is refused. |
| A3: an environment-derived lock base gives two agents | Applied in §1: the base comes from the OS user identity, never `$XDG_*` or `$TMPDIR`. `agent enable` records it, and an agent on a different base refuses to start. |
| A4 / F2: the same-user exposure is not stated | Applied in §2: the trust boundary is stated, with what it grants and an audit line per mutation. The capability token is rejected, with the reason. |
| A5 / F-07: MCP confused deputy, `discover_hosts` | Applied in §5: no discovery, import or credential in MCP. `destructiveHint` is set on stop, and the ADR says annotations are not authorization. |

## Review: `nan/deepseek-v4-flash`

### Verdict: **PASS-WITH-GAPS**

The chosen option (B: per-user agent + thin clients) survives refutation — it matches 4 of the 5 named references and reuses the ADR-016 lock. But two *Blockers* show that stated constraints **G-C5** (no duplicates) and **G-C7** (caller identity) are not met by the design as written, and the central rationalisation ("the agent adds a mode and replaces nothing", §6) is false in four separate places in the code it claims to reuse. Close A1, A3, B1, B2, C1 in the ADR text before #782 implements.

Read in full: `docs/adr/adr-018-local-control-plane.md`, `docs/design/gui-control-plane-reference-audit.md`, ADR-015, ADR-016, ADR-017, `cmd/cli/{connect,run,discover,signal,profile_credentials}.go`, `internal/{profile,logging,config}`, `internal/bootstrapssh/`, go.mod.

| A1 | **Blocker** | Local API security | §2 "Windows: a named pipe that includes the user's SID, with an SDDL granting only that SID. Each connection checks the client process token's SID" — implies the pipe is the agent's | The DACL governs connections to *an instance the agent created*; the `\\.\pipe\` namespace is global and first-creator-wins. The name embeds the SID, which is public (it is in every ACL). A process of another user — or a same-user process launched at logon before the agent — can create `\\.\pipe\<sid>-ts-bridge` first; the agent's `CreateNamedPipe` then fails, and the *tray/MCP client* that connects posts the ADR-015 node key as part of `import`. | A2 | Major | Local API security | §2 "the user cache directory on macOS" | Undefined path, and it contradicts the established base: `internal/config/statedir.go:90` puts everything under `~/Library/Application Support/ts-bridge/`, and ADR-015 pins the credential store to that same root. `~/Library/Caches` is OS-purgeable and has no privacy contract across macOS versions. | A3 | **Blocker** | Local API security / process | §1 "One agent per user, guarded by an OS-backed lock in the user's state directory… never a PID file" satisfies G-C5 | The state dir is env-derived with a temp fallback: `statedir.go:93-95` honours `XDG_STATE_HOME`, `:39` falls back to `$TMPDIR/ts-bridge/state`. | A4 | Major | Local API security | G-C7 / Rationale: "identity-checked local socket" as a security property | uid equality is the whole check: `SO_PEERCRED`/`getpeereid` prove same-user only (macOS returns euid/egid — no pid, no image, so the caller cannot even be named in an audit line). | A5 | Major | Local API security | §5 "`readOnlyHint` on the reads and without it on start and stop (G-C8)" as the safety model | Annotations are *client* hints that enable auto-approval; nothing in the design gates a mutating call. `discover_hosts` would make the agent call an admin-scope control plane with a key the MCP client never sees — the confused deputy in one line — while ADR-015 confirms administrative credentials are "not persisted by default" (constraint 8, Option C rejected). | Either drop `discover_hosts` from §5 (and add a follow-up ticket for an ADR-015 admin-credential story) or gate every mutating tool on a confirmation the *agent* surfaces through the tray; state that annotations are not authorization. |
| A6 | Minor | Local API security / contract | G-C9 "Credentials stay in the ADR-015 store, and the GUI holds no secrets" | The first-run form (§4) has the user paste the key into a WebView: DOM, JS heap, engine autofill/restore, and the Wails bridge serialise it. ADR-015 constraint 2 enumerates argv/stdout/stderr/logs/transcripts — not a webview and not a local socket; the `import` endpoint makes the socket a new credential transport. | Reword G-C9 to "persists no secret"; amend ADR-015 for the socket transport; or move first-run credential entry out of the webview (agent-owned native masked dialog, or a spawned `ts-bridge import`/`auth set`). |
| B1 | **Blocker** | Process model | §1 "the agent passes each child a lifeline pipe, and the child exits when the pipe reaches EOF" + §6 "The agent adds a mode and replaces nothing" | `connect` reads no stdin at all: `cmd/cli/run.go:165-190` watches only SIGINT/SIGTERM, and `os.Stdin` is handed verbatim to the SSH bootstrap child (`internal/bootstrapssh/bootstrap.go:99`). | B2 | Major | Process model | §2 `stop` as a first-class API verb on all three OSes | `signal.NotifyContext(ctx, SIGINT, SIGTERM)` (`run.go:166`) never fires for a console-less Windows child; `os.Process.Signal` cannot deliver SIGTERM there; the job-object kill bypasses `--drain-timeout`/`drainActiveConnections` (`run.go:341-360`); the child's health server has no control verb (`internal/health/health.go:77-105`). | B3 | Major | Process model | §1 "Windows adds a Job Object with kill-on-close" presented alongside the lifeline as sufficient | Assign-after-start is a race: the child runs before `AssignProcessToJobObject`, so anything it spawns first escapes — the repo's own containment code documents exactly this (`internal/bootstrapssh/contain_windows.go:20-24`: "a process ssh spawns before the assignment… is not in the job", and "a parent job that forbids nesting makes the assignment fail"). | B4 | Major | Process model | §1 "Recovery: the agent records which profiles should be running… After a restart it brings back the sessions that were running", plus Consequences "Sessions survive… an agent restart" | No retry budget, backoff, attempt cap, or failure memory. | F4 | Minor | Claims vs evidence | "Four of the five references have one process own the sessions" + O. | F3 | Minor | Claims vs evidence | "Every macOS tray path therefore needs cgo" | Same as E1 from the evidence side: `fyne.io/systray` was measured cgo-only-on-macOS, so "every path" is true but useless — the constraint it is played against (G-C4) does not bind a separate module. | Fold into the E1 rewrite. |

### The 3 changes that matter most

1. **Anchor identity in the OS, not in the environment, and authenticate both ends of the pipe.** One env-independent base for the agent lock, the per-profile lock and the socket, with a refusal on mismatch (`agent enable` records it), no `$TMPDIR`/XDG escape (A3, A2); on Windows `FILE_FLAG_FIRST_PIPE_INSTANCE` + client-side server verification before any credential is sent (A1). Without this, two stated constraints — G-C5 and G-C7 — are prose only, and the first-run flow is a credential-theft path.
2. **Write the child contract as a new public contract instead of claiming reuse.** Lifeline as an explicit opt-in flag with defined stdin semantics (B1), bidirectional `STOP` so Windows has a graceful stop at all (B2), `READY`/`ERROR` adopted as the session ABI with `--quiet` and exit-code mapping (B5), fixed CWD + scrubbed env (B9), per-session logs (B8). "Adds a mode and replaces nothing" is the ADR's load-bearing simplification and it is currently false.
3. **One supervisor owns restarts, and the session set has a defined failure policy.** The tray asks launchd/systemd/Task Scheduler and never execs when a registration exists (C1) — the current text guarantees a launchd restart storm; and the desired-running set needs a state machine with a retry budget and a terminal `failed` state (B4) instead of an unbounded crash loop.

## Review: `agy/gemini-3.8-flash-high`

### Verdict

**FAIL**

ADR-018 cannot be accepted in its current form. It relies on platform-incompatible IPC mechanisms (Go `os/exec` on Windows does not support `ExtraFiles` for lifeline pipes), introduces high-risk security flaws on local endpoints (Windows named pipe squatting without `FILE_FLAG_FIRST_PIPE_INSTANCE`, macOS socket placement in world-readable cache directories exceeding 104-byte limits), contains a dual-supervisor race condition between the tray and OS service managers that causes systemd to lock units in failed states, and makes architectural claims directly refuted by its own reference audit.

### The 3 Changes That Matter Most (In Order)

1. **Resolve Windows Named Pipe & Lifeline IPC Flaws (F-01, F-03)**
   - **Why it matters**: Pipe squatting is an exploitable local credential theft vulnerability on multi-user Windows machines, and assuming POSIX file-descriptor inheritance works for lifeline pipes on Windows in Go will break child process lifecycle management on day one.
   - **Action**: Add `FILE_FLAG_FIRST_PIPE_INSTANCE` and client-side server SID validation. Replace abstract lifeline pipe claims with explicit Win32 inheritable handle passing (`AdditionalInheritedHandles`) and a lifeline monitoring goroutine in `cmd/cli/run.go`.

2. **Eliminate the Dual-Supervisor Crash Loop Race (F-04, F-08, F-10)**
   - **Why it matters**: A race between the tray and the OS service manager will cause systemd to hit `StartLimitBurst` and permanently mark the agent as failed, while unthrottled restarts of failing profiles will cause a local fork bomb.
   - **Action**: Forbid the tray from spawning the agent when an OS supervisor is configured (delegate to `systemctl`/`launchctl`/`schtasks`). Add exponential backoff and a 3-strike failure limit to profile recovery in the agent. Configure launchd with `SuccessfulExit=false`.

3. **Fix macOS Socket Path & Reconcile Audit Evidence (F-02, F-05, F-12)**
   - **Why it matters**: Placing domain sockets in `~/Library/Caches` breaks path length limits (`< 104` bytes) and exposes sockets in world-readable directories. Furthermore, citing Tailscale macOS as precedent for Unix sockets directly contradicts the design audit evidence.
   - **Action**: Relocate the macOS socket to a verified `0700` application support directory with a strict `< 104` byte assertion. Correct the reference audit text to reflect Tailscale's actual macOS IPC architecture (`localhost` TCP + `sameuserproof`).
